## Critical Rules (Always Apply)

These are the highest-impact rules. Full standards live in `.claude/rules/`.

- **§0.1 IMPORTANT:** WHEN editing `DbConfigDbContext.OnModelCreating`, DO NOT add `ToTable`/`HasColumnName` name literals — identifiers come from EF defaults + per-provider naming conventions; literals break PostgreSQL snake_case queries at runtime. (`DbConfigDbContext.cs`)
- **§0.2 IMPORTANT:** NEVER persist a value marked `IsSecret` through `PassthroughConfigEncryptor` (no-op) outside tests — register a real `IConfigEncryptor` first. (`PassthroughConfigEncryptor.cs`)
- **§0.3** WHEN adding read queries to an EF store, DO NOT omit `AsNoTracking()` — every existing read uses it. (`EfCoreConfigStore.cs`)
- **§0.4** Builds run `TreatWarningsAsErrors=true` + analyzers (StyleCop/Roslynator/Sonar/Meziantou). NEVER suppress a warning to make the build pass without justifying it in code.
- **§0.5** WHEN adding HTTP behavior, use minimal-API `{Verb}{Entity}Endpoint` classes — DO NOT introduce MVC controllers; none exist.

## Project Profile

- **Framework:** .NET 8 (`net8.0`); NuGet library (database-backed `IConfiguration` provider)
- **Data layer:** EF Core 8 (shared `DbConfigDbContext`); PostgreSQL (Npgsql) + SQL Server providers; snake_case via EFCore.NamingConventions
- **Patterns:** IConfiguration provider/source, fluent `DbConfigBuilder` DI, minimal-API endpoints, pluggable encryption + auth, multi-tenancy
- **Hosting:** library — hosted by consuming apps; no IaC/containers (Testcontainers only in tests)
- **Database:** PostgreSQL, SQL Server
- **Test stack:** xUnit v3 (MTP runner) + Shouldly + Moq + Testcontainers (PG/MsSql) + Respawn + InMemory + TimeProvider.Testing

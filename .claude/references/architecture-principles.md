## 3. Design Patterns in Use

### 3.1 IConfiguration provider/source
- [EXTRACTED] Implements the standard ASP.NET Core configuration extensibility pattern: a `ConfigurationSource` builds a `ConfigurationProvider`. Evidence: `DbConfigConfigurationSource.cs`, `DbConfigConfigurationProvider.cs` in `DbConfig.Core`.

### 3.2 Options + fluent builder DI
- [EXTRACTED] Registration is via a fluent `DbConfigBuilder` over `IServiceCollection`, with `AddDbConfig`-style entry points and provider extension methods. Evidence: `DbConfigBuilder.cs:12` (`internal DbConfigBuilder(IServiceCollection services, DbConfigOptions options)`), `DbConfigBuilderEfCoreExtensions.cs`, `DbConfigBuilderPostgreSqlExtensions.cs`, `DbConfigBuilderSqlServerExtensions.cs`.
- [EXTRACTED] DI uses `TryAdd*` to let host-supplied implementations win (e.g. a custom `IConfigEncryptor` registered before `AddDbConfig` is not overwritten). Evidence: `IConfigEncryptor.cs:9-11`, `DataProtectionConfigEncryptor.cs:14`.

### 3.3 Minimal-API endpoints (no MVC controllers)

Evidence: 7 `*Endpoint.cs` files in `DbConfig.Http/Endpoints/` (`find src/core -name "*Endpoint.cs"` → 7); `GetEntryEndpoint.cs` (`internal static async Task HandleAsync(...)`). No `*Controller.cs` exists: `find . -name "*Controller*.cs"` → none.
- [INFERRED:0.9] No CQRS/MediatR mediator is used — handlers call store interfaces directly. Evidence: `grep -rl "IRequest|IRequestHandler|IMediator" --include="*.cs" .` → 0 hits; no MediatR package reference.

### 3.4 Pluggable encryption / secret protection
- [EXTRACTED] `IConfigEncryptor` abstracts secret protection; `DataProtectionConfigEncryptor` (ASP.NET Data Protection) is the EF/provider default, `PassthroughConfigEncryptor` (no-op) is the in-memory default. ## 10. Inconsistencies Found

- [AMBIGUOUS] UI authorization posture is split by overload: the two-arg `MapDbConfigUi` is intentionally fully open, while richer overloads wire `LocalRequestsOnlyAuthorizationFilter` or `CookieAuthorizationFilter`. This is documented backwards-compat, but means "secure by default" is NOT the default. Evidence: `OpenAccessByDefaultTests.cs`, `EndpointRouteBuilderExtensions.cs:79-103`. Team decision: whether to flip the default in a future major.
- ⚠️ The default in-memory encryptor is `PassthroughConfigEncryptor` (no-op). Acceptable for tests, but any non-EF/in-memory path that stores secrets without registering a real `IConfigEncryptor` persists plaintext. Evidence: `PassthroughConfigEncryptor.cs`. Opportunity: fail-fast or warn when `IsSecret=true` values are written under passthrough.

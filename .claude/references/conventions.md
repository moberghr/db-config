## Naming Conventions
- **HTTP endpoints:** `{Verb}{Entity}Endpoint` static classes with an `internal static async Task HandleAsync(...)` method (e.g. `GetEntryEndpoint`, `UpsertEntryEndpoint`, `DeleteEntryEndpoint`). 7/7 endpoint files follow this. `[CONVENTION]`
- **Controllers:** none — this codebase uses minimal-API endpoints, not MVC controllers (`find . -name "*Controller*.cs"` → 0). `[ENFORCED]` (absence verified)
- **Abstractions:** interfaces are `I{Capability}` in `DbConfig.Core` (e.g. `IConfigStore`, `IConfigReader`, `ITenantResolver`); records are `{Thing}Record` (`ConfigEntryRecord`, `ConfigAuditEntryRecord`). `[CONVENTION]`
- **Tests:** `{Subject}Tests` sealed classes (84/84 `*Tests.cs`). `[CONVENTION]`
- **Logger markers:** dedicated `{Endpoint}Marker` types used as `ILogger<T>` category. `[CONVENTION]`

## File Organization
- Package-per-concern under `src/core/` (`DbConfig.Core`, `DbConfig.EntityFrameworkCore`, `DbConfig.Http`, `DbConfig.Ui`); DB providers under `src/core/providers/`. New persistence behavior goes in `DbConfig.EntityFrameworkCore` or a provider package; new HTTP behavior in `DbConfig.Http/Endpoints/`.
- Abstractions live in `DbConfig.Core`; concrete impls depend on Core, never the reverse.
- Tests mirror layers: `src/tests/DbConfig.Tests/{Core,EntityFrameworkCore,Http,Ui,PostgreSql,SqlServer,E2E}/`.

## DI Registration
- Fluent `DbConfigBuilder` over `IServiceCollection`; provider/EF extension methods (`UseEntityFrameworkCore`, `UsePostgreSql`, `UseSqlServer`) extend the builder.
- Use `TryAdd*` so a host-registered implementation (encryptor, tenant resolver, credential validator) wins over the default. `[CONVENTION]`
- Lifetimes: `AddSingleton` for resolvers/encryptors; `AddScoped` for request-bound services (credential validators).

## Response & Error Handling
- HTTP endpoints serialize with `System.Text.Json` via shared `JsonOptions.Default`.
- 404/empty results set `HttpContext.Response.StatusCode` directly rather than returning a typed result envelope. No `Result<T>`/`ProblemDetails` envelope is used. `[CONVENTION]`
- Audit/observability side-effects degrade gracefully (warn-once, fire-and-forget) rather than throwing on misconfiguration.

## Test Conventions
- xUnit v3 on Microsoft Testing Platform runner; **Shouldly** for assertions (NOT FluentAssertions — 84/84 test files use Shouldly); Moq for mocks. `[ENFORCED]` (build runner)
- `IAsyncLifetime` fixtures; Testcontainers (PostgreSQL + SQL Server) + Respawn for real-engine integration tests; `TimeProvider.Testing` for clock control.
- Prefer real relational providers (Testcontainers) when query translation/relational semantics matter; reserve `EntityFrameworkCore.InMemory` for behavior that doesn't.
- Tag tests with `[Trait("Category", "...")]`.

## Other Patterns
- All projects target `net8.0`; package versions are declared inline per `.csproj` (no `Directory.Packages.props`).
- `TreatWarningsAsErrors=true` and `EnforceCodeStyleInBuild=true` are repo-wide — builds fail on analyzer/style violations.
- EF `OnModelCreating` must contain NO table/column name literals; naming comes from EF defaults + per-provider naming conventions (PostgreSQL snake_case, SQL Server PascalCase). `[ENFORCED]` (breaks PG queries otherwise)

## Cross-Cutting Concerns

- **Logging:** every public surface uses `ILogger<T>`; reload failures log at Warning; store mutations at Information.
- **TimeProvider:** all timer logic injects `TimeProvider` (defaulted to `TimeProvider.System` via `TryAddSingleton`). Per architecture-principles §5.
- **Scoped DbContext:** EF Core registration uses `AddDbContextFactory` for the polling provider (no scope at host construction time), `AddDbContext` for HTTP. Per architecture-principles §6.
- **No raw SQL:** all queries LINQ. Per architecture-principles §3.
- **Both DB engines:** every store-touching test inherits a shared base with engine-specific fixtures. Per architecture-principles §8.

## Review

After Batch 9: spec-drift check + Stage 1 compliance review + Stage 2 (test-reviewer + architecture-reviewer) per `implement` Phase 4.

## Rollback / De-scope

If timeline tightens, the natural cut line is **Batch 7 (PostgreSQL)** — ship v0.1.0 with SQL Server only and follow up with PG in v0.2.0. Skipping the UI (Batches 4-6) is also possible — ship a Core+Http v0.1.0 and add UI as v0.2.0, since the HTTP API is a complete editor surface on its own. Not recommended: skipping Batch 9 (E2E tests).

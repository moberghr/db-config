## B21 — Encryption: `IConfigEncryptor` + `DataProtectionConfigEncryptor` + store integration

**Goal:** Per-entry encryption tied to `IsSecret`. `EfCoreConfigStore` encrypts on upsert when `IsSecret=true`; decrypts on read. `InMemoryConfigStore` mirrors the behavior for test parity.

**Files:**
- ✱ `src/core/DbConfig.Core/IConfigEncryptor.cs` — interface (in `DbConfig.Core` namespace)
- ✱ `src/core/DbConfig.Core/PassthroughConfigEncryptor.cs` — internal no-op impl used when no encryptor is registered (returns plaintext both ways); makes tests that don't care about encryption simple
- ✱ `src/core/DbConfig.EntityFrameworkCore/DataProtectionConfigEncryptor.cs` — wraps `IDataProtector`
- △ `src/core/DbConfig.EntityFrameworkCore/DbConfigBuilderEfCoreExtensions.cs` — register encryptor: `services.TryAddSingleton<IConfigEncryptor, DataProtectionConfigEncryptor>()` + ensure DataProtection services are present via `services.AddDataProtection()` (which is internally TryAdd-based)
- △ `src/core/DbConfig.EntityFrameworkCore/EfCoreConfigStore.cs` — constructor accepts `IConfigEncryptor`; `UpsertAsync` encrypts value when `entry.IsSecret`; read paths (`GetAsync`, `GetAllAsync`, `GetAllScopedAsync`) decrypt secret values before mapping to `ConfigEntry`
- △ `src/core/DbConfig.Core/InMemoryConfigStore.cs` — accepts optional `IConfigEncryptor` (defaults to `PassthroughConfigEncryptor`); same encrypt-on-upsert / decrypt-on-read semantics so tests can exercise encrypted flow without Data Protection setup
- △ `src/core/DbConfig.Core/HostApplicationBuilderExtensions.cs` (the single-call AddDbConfig) — also constructs the polling-side encryptor instance (Data Protection-backed, using a side-built `IDataProtectionProvider` or by adding minimal DataProtection services to a transient SP — see below)
- ✱ `src/tests/DbConfig.Tests/Core/PassthroughConfigEncryptorTests.cs`
- ✱ `src/tests/DbConfig.Tests/EntityFrameworkCore/DataProtectionConfigEncryptorTests.cs` — round-trip + key-rotation safety
- ✱ `src/tests/DbConfig.Tests/SqlServer/SqlServerStoreEncryptionTests.cs` — verifies ciphertext-at-rest by reading the row directly with `DbContext.ConfigEntries.AsNoTracking().FirstOrDefaultAsync(e => e.Key == "X")` and asserting the raw `.Value` does NOT equal the plaintext
- ✱ `src/tests/DbConfig.Tests/PostgreSql/PostgreSqlStoreEncryptionTests.cs` — same pattern
- △ `src/tests/DbConfig.Tests/SqlServer/SqlServerFixture.cs` + `PostgreSqlFixture.cs` — wire a deterministic test encryptor (ephemeral Data Protection ring) so tests are repeatable

**Polling-side encryptor:** the single-call `AddDbConfig` extension currently builds the polling-side `EfCoreConfigStore` directly (no DI lookup). It needs to construct an `IConfigEncryptor` instance too. Cleanest: build a minimal `IServiceCollection` containing just DataProtection services + resolve `IConfigEncryptor` from it. OR pass the host's `IDataProtectionProvider` once it's available (won't be at this stage). Easiest: instantiate a `DataProtectionConfigEncryptor` from `DataProtectionProvider.Create(new DirectoryInfo(...))` with a sensible default key location. We'll go with: instantiate a singleton `IDataProtectionProvider` once (filesystem keys at `%LOCALAPPDATA%/DbConfig/Keys` by default; configurable via `DbConfigOptions.KeyDirectory`). Document the customization story.

Actually simpler: since the HTTP-side store uses `services.AddDataProtection()`, we BUILD a temporary SP from a clone of the marker-stored services to get an `IDataProtectionProvider`, then use it for both stores. This is a controlled second SP (transient, used once at startup), justified for shared key access. Document the design choice.

**Verification:** build clean; suite 128 → ~145.

**Boundary:** Core + EFC + their test folders.

**Depends:** none.

## B25 — Collation fix: case-sensitive scope columns on both DBs

**Goal:** `Scope`, `Environment`, `Key` columns on both `DbConfig_Entries` and `DbConfig_AuditEntries` get case-sensitive binary collations. This closes the v0.4.0 M2 finding.

**Files:**
- △ `src/core/DbConfig.EntityFrameworkCore/DbConfigDbContext.cs` — `.UseCollation(...)` per column in `OnModelCreating`. Provider-specific via `Database.IsSqlServer()` / `Database.IsNpgsql()` check or per-provider override.

  Actually: collation needs to be set per provider. Cleanest is to expose a virtual `OnModelCreating` and override in provider-specific `DbContext` subclasses — but db-config has ONE `DbContext` shared across providers. Alternative: use `DbContextOptionsBuilder` to inject a provider-specific configuration callback. Yet another option: do it in the migrations (each provider's migration sets the right collation for that DB).

  **Pick the migrations path:** the migration is already provider-specific. The SqlServer migration uses `Latin1_General_100_BIN2`; the PG migration uses `"C"`. EF model annotations stay collation-agnostic.

- ✱ `src/core/providers/DbConfig.Provider.SqlServer/Migrations/20260517000001_CaseSensitiveScopeColumns.cs` (+ Designer + ModelSnapshot)
- ✱ `src/core/providers/DbConfig.Provider.PostgreSql/Migrations/20260517000001_CaseSensitiveScopeColumns.cs` (+ same)
- ✱ `src/tests/DbConfig.Tests/SqlServer/SqlServerCollationTests.cs`:
  - `ScopeCaseSensitive_DifferentCaseInQuery_NoRowsReturned` — insert Scope='MyApp', query with 'myapp', expect zero rows
  - Same for Environment, Key
- ✱ `src/tests/DbConfig.Tests/PostgreSql/PostgreSqlCollationTests.cs` — same

**Verification:** build clean; suite ~165 → ~171.

**Boundary:** EFC + provider migrations + test folders.

**Depends:** B22 (audit table must exist before we collate its columns).

## B26 — Cleanup: ScopeSelector setTimeout + SpinWait test patterns

**Goal:** Close two pre-existing minor smells flagged in earlier reviews.

**Files:**
- △ `ui/src/components/ScopeSelector.tsx` — remove `setTimeout(0, refresh)` hack. Replace with explicit state passing: the form's "Switch" button calls `setScope(...)` then `refresh()` with the NEW values passed explicitly (`refresh({scope: newApp, environment: newEnv, includeScopes: newScopes})`). This requires updating `entriesStore.refresh` to accept an optional overrides arg.
- △ `ui/src/store/entriesStore.ts` — `refresh(overrides?: { scope?: string; environment?: string; includeScopes?: string[] })`. When overrides are passed, use those instead of reading from `scopeStore.getState()`. Documented as the "fresh-state path" for callers that just set the store and want to use NEW values without waiting for React reconciliation.
- △ `src/tests/DbConfig.Tests/Core/PollingReloadTests.cs` — replace `SpinWait.SpinUntil(...)` patterns with signal-based waits. Pattern: introduce a `TaskCompletionSource<bool>` set by the test's wrapper `IConfigStore`'s `GetLatestModifiedUtcAsync` callback. Tests `await tcs.Task.WaitAsync(TimeSpan.FromSeconds(5))` instead of polling. (FakeTimeProvider still drives the timer; the TCS just lets the test know when the tick completed.)
- △ `src/tests/DbConfig.Tests/Core/IncludeScopesPrecedenceTests.cs` — same SpinWait → TCS replacement.

**Verification:** build clean; UI build clean; suite ~171/171 unchanged (refactor only).

**Boundary:** UI + Core test files only.

**Depends:** none (independent cleanup).

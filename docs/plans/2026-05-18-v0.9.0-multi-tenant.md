## B62 — Refactor: ITenantResolver + standard IOptionsSnapshot (final design)

**Goal:** Replace the over-engineered three-layer abstraction (`ITenantContextAccessor` / `ITenantConfigReader` / `ITenantAwareOptions<T>`) with a simpler design:

- `ITenantResolver` — single consumer-implemented interface, one method `string? Resolve()`
- `b.AddTenantResolver<TResolver>()` — registration inside the `AddDbConfig` block
- `DbConfigConfigurationProvider.TryGet` — consults the resolver on every read; tenant-specific entry wins, global fallback if missing
- Standard `IOptionsSnapshot<T>` — automatically tenant-aware because it binds from `IConfiguration` per scope; no custom options API needed

**What was removed:** `ITenantContextAccessor`, `DefaultTenantContextAccessor`, `ITenantConfigReader`, `ITenantAwareOptions<T>`, `TenantAwareOptions<T>`, `TenantAwareOptionsBuilder`, `AddTenantAwareOptions` extension.

**What was added:** `ITenantResolver`, `NullTenantResolver` (internal), `DbConfigBuilder.AddTenantResolver<T>()`.

**Demo updated:** `Program.cs` switched from `SetTenant()` middleware to `DemoTenantResolver` class reading `X-Tenant-Id` header.

**Verification:** dotnet build clean; 287 tests pass (net -17 from removed abstraction tests, +3 from new resolver tests).

**Depends:** B55, B56.

## Cross-cutting

- Each batch ends green: `dotnet build src/DbConfig.slnx`, `./DbConfig.Tests.exe`, `cd ui && npm run build`
- Memory ceiling documented: ~10K tenants × 100 keys is the v0.9.0 sweet spot; lazy-load is v0.10.0+ if needed
- **Final design note:** the B62 refactor reduced the public surface significantly. The new design is: consumer implements `ITenantResolver`; `IConfiguration[key]` becomes tenant-aware; `IOptionsSnapshot<T>` rides on top. The IOptions<T> gotcha (singleton caching) is documented prominently in two places.

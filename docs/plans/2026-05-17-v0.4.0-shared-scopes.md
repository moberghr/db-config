## B17 — HTTP API: `?includeScopes=` on list endpoint + merged view

**Goal:** `GET /{app}/{env}?includeScopes=Shared,PlatformDefaults` returns merged entries from all listed scopes plus the path's `{app}`, each row carrying its source `scope`. Default (no query) is unchanged.

**Files:**
- △ `src/core/DbConfig.Http/Endpoints/ListEntriesEndpoint.cs` — accept `includeScopes` query string (comma-separated). When present, call `store.GetAllScopedAsync(scopes + scope, env)`.
- ✱ `src/tests/DbConfig.Tests/Http/ListEndpointIncludeScopesTests.cs`:
  - `List_WithIncludeScopes_ReturnsMergedRows`
  - `List_WithIncludeScopes_PrecedenceAppliedToDuplicateKeys` (each row preserves its source Scope; merging is the consumer's job — server returns ALL rows ordered lowest-precedence-first, with own scope last)
  - `List_WithoutIncludeScopes_ReturnsOnlyOwnScope` (regression guard)

**Decision:** the server returns **all rows**, not pre-merged. The polling provider merges (because it has to fold into the dictionary anyway); the UI merges (because it needs to show source badges). This is simpler than two-way duplication and lets the UI render a "shadowed by override" indicator.

**Verification:** build clean; suite ~97 → ~100.

**Boundary:** Http + Http tests.

**Depends:** B15 (for the InMemoryConfigStore impl that tests use).

## B18 — `MapDbConfigHttp` `scopeFilter` overload

**Goal:** Per-scope auth grouping. When `scopeFilter` is non-null, all endpoints under that group reject mismatched `{scope}` paths with 403.

**Files:**
- △ `src/core/DbConfig.Http/EndpointRouteBuilderExtensions.cs` — add `scopeFilter` parameter; install an `IEndpointFilter` that checks `httpContext.Request.RouteValues["scope"] == scopeFilter`
- △ `src/core/DbConfig.Http/Endpoints/*` — no changes (the filter sits at the group level)
- ✱ `src/tests/DbConfig.Tests/Http/MapDbConfigHttpScopeFilterTests.cs`:
  - `ScopeFilter_MatchingScope_ProceedsToHandler`
  - `ScopeFilter_NonMatchingScope_Returns403`
  - `ScopeFilter_OnReloadEndpoint_AlwaysAllowed` (reload has no scope in route)
  - `WithoutScopeFilter_AllScopesAllowed` (regression)

**Verification:** build clean; suite ~100 → ~104.

**Boundary:** Http + Http tests.

**Depends:** B17.

## B19 — UI: scope badge + view filter + per-row write guard

**Goal:** UI surfaces the scope each entry came from; user can toggle Mine / Shared / All view; edit/delete blocked on cross-scope rows.

**Files:**
- △ `ui/src/api/client.ts` — `listEntries` accepts optional `includeScopes: string[]` parameter; serializes to comma-separated query string
- △ `ui/src/api/entries.ts` — `ConfigEntry` type already has `scope`; expose it on the list response
- △ `ui/src/store/scopeStore.ts` — add `includeScopes: string[]` and `viewMode: 'mine' | 'shared' | 'all'` (default 'all'); persist to localStorage
- △ `ui/src/store/entriesStore.ts` — pass `includeScopes` into `listEntries`; client-side filter by `viewMode`
- △ `ui/src/components/EntriesTable.tsx` — new "Scope" column showing `entry.scope` with a colored badge (own scope = primary, shared = secondary); disable Edit/Delete buttons on rows where `entry.scope !== scopeStore.scope`
- ✱ `ui/src/components/ViewModeToggle.tsx` — Mine / Shared / All segmented control bound to `scopeStore.viewMode`
- △ `ui/src/components/CreateEntryDialog.tsx` — add scope selector (defaults to current `scopeStore.scope`); locked if only one scope known
- △ `ui/src/components/ScopeSelector.tsx` — second input for comma-separated `IncludeScopes`
- △ `ui/src/pages/EntriesPage.tsx` — wire `ViewModeToggle`

**Verification:** `cd ui && npm run build` — clean. No new tests in this batch (UI test infra deferred).

**Boundary:** ui/src/ only.

**Depends:** B17 (server returns scope info), B18 (scopeFilter awareness for write guard).

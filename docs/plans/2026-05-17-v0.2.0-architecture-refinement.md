## Batch B11 — Two-call `AddDbConfig` DI redesign

**Goal:** Eliminate the inner `ServiceCollection` and the `IDbConfigReloadSignal` bridge dance. Host owns all DbConfig services directly.

**Files:**
- △ `src/core/DbConfig.Core/ConfigurationBuilderExtensions.cs` — replace `(IConfigurationBuilder, Action<DbConfigBuilder>)` with `(IConfigurationBuilder)` (no lambda). Add a sibling `AddDbConfig(IConfigurationBuilder, IServiceCollection)` overload for hosts that don't expose Properties.
- ✱ `src/core/DbConfig.Core/ServiceCollectionExtensions.cs` — new `AddDbConfig(this IServiceCollection, Action<DbConfigBuilder>)`; registers options, `IConfigStore`, `IDbConfigReloadSignal`, the polling provider source, and stashes a `DbConfigBuilder` snapshot keyed by the `IServiceCollection` instance.
- △ `src/core/DbConfig.Core/DbConfigBuilder.cs` — `Services` now references the host's `IServiceCollection` directly (passed via ctor). XML doc updated.
- △ `src/core/DbConfig.Core/DbConfigConfigurationSource.cs` — resolves `IConfigStore` from the supplied `IServiceProvider` (built once after the host's services are configured)
- △ `src/core/DbConfig.Core/DbConfigConfigurationProvider.cs` — no functional change, but accept services from the source
- △ `src/demo/DbConfig.Demo.WebApp/Program.cs` — update to two-call shape; drop the `IConfigurationRoot.Providers.OfType<>` bridge
- △ `src/tests/DbConfig.Tests/E2E/EndToEndFixture.cs` + `EndToEndPostgreSqlFixture.cs` — same update
- △ `src/tests/DbConfig.Tests/Http/EndpointContractTests.cs`, `EndpointAuthCompositionTests.cs`, `ReloadEndpointTests.cs` — adapt to new shape (or stay using direct `MapDbConfigHttp` registration which doesn't go through `AddDbConfig`)
- △ `src/tests/DbConfig.Tests/Core/AddDbConfigContractTests.cs` — update assertions for new shape
- ✱ `src/tests/DbConfig.Tests/Core/AddDbConfigTwoCallShapeTests.cs` — three new tests:
  - `BothCalls_RegistersSourceAndServices_HappyPath`
  - `OnlyServicesCall_NoConfigurationCall_ServicesRegisteredButSourceMissing`
  - `OnlyConfigurationCall_NoServicesCall_ThrowsInvalidOperationException`

**Verification:**
- Build clean. Full suite green (≥ 69 + 3 new = 72).
- Demo `Program.cs` should now be visibly shorter (the bridge `AddSingleton<IDbConfigReloadSignal>(sp => ...)` block is gone).

**Boundary:** files listed above. Other batches' files are out of bounds.

**Depends:** B10 (so endpoint tests already use the new `GetAsync` path).

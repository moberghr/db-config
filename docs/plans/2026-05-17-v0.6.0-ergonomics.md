## B32 — Type-mapped IConfigEncryptor

**Goal:** Standard DI registration syntax works. Polling-side decryption deferred until host is built.

**Files:**
- △ `src/core/DbConfig.Core/DbConfigConfigurationProvider.cs`:
  - Field: `private IConfigEncryptor? _encryptor;`
  - Method: `internal void SetEncryptor(IConfigEncryptor encryptor) { _encryptor = encryptor; ReloadDecryptedView(); }`
  - Override `TryGet(string key, out string? value)`: if the underlying dictionary value is non-null AND the entry is marked secret (we need to track this — see below), decrypt via `_encryptor`. If `_encryptor` is null AND secret → throw `InvalidOperationException("Cannot read secret value 'X' before host.Build() returned. Move the read into a request handler or post-build callback.")`. Non-secret values are returned as-is.
  - Need a parallel `Dictionary<string, bool> _isSecret` to track which keys are secret. Populated during Load() from the store's ConfigEntry stream.
- △ `src/core/DbConfig.EntityFrameworkCore/EfCoreConfigStore.cs`:
  - When the polling-side instance has a null encryptor, it returns raw values (ciphertext for secret rows). This means `ConfigEntry.Value` returned from the store is ciphertext for secrets in the polling-side path.
  - The HTTP-side store (DI-resolved, has the encryptor) continues to decrypt on read.
- ✱ `src/core/DbConfig.EntityFrameworkCore/DbConfigEncryptorActivator.cs`:
  - `IHostedService` that resolves `IConfigEncryptor` from the host SP in `StartAsync` and calls `provider.SetEncryptor(...)`.
  - Registered in `HostApplicationBuilderExtensions.AddDbConfig` via `services.AddHostedService<DbConfigEncryptorActivator>()`.
  - Constructor takes `IConfigEncryptor`, `DbConfigRegistrationMarker` (to access the provider).
- △ `src/core/DbConfig.EntityFrameworkCore/HostApplicationBuilderExtensions.cs`:
  - If `ImplementationInstance` exists, behavior unchanged (instance is shared synchronously).
  - If `ImplementationInstance` doesn't exist BUT a service registration does (type-mapped or factory) → register the activator hosted service; pass null encryptor to the polling store.
  - If no encryption registration at all → construct default DataProtection encryptor as before (and share instance with polling store).

**Tests:**
- ✱ `src/tests/DbConfig.Tests/Core/TypeMappedEncryptorTests.cs`:
  - `TypeMappedRegistration_AfterHostBuild_DecryptsCorrectly`
  - `TypeMappedRegistration_ReadSecretBeforeBuild_Throws`
  - `TypeMappedRegistration_ReadNonSecretBeforeBuild_Succeeds`
  - `TypeMappedRegistration_WithDependencies_ResolvesCorrectly` (encryptor has ILogger ctor param)
  - `InstanceRegistration_StillWorks` (regression for v0.5.0 fix)

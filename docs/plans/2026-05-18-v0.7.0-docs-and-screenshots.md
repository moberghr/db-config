## B35 — UI demo mode

**Goal:** `?demo` query string OR `--mode demo` Vite startup activates an in-memory adapter that mimics the HTTP API. UI is fully navigable with realistic data; mutations are local-state.

**Files:**
- ✱ `ui/src/demo/data.ts` — typed snapshot of `ConfigEntry[]` (~20 entries across 3 scopes) + `ConfigAuditEntry[]` (3–5 per key) + IDS for stable lookup. Deterministic timestamps relative to a captured `NOW`.
- ✱ `ui/src/demo/adapter.ts` — `createDemoClient()` exposing the same shape as the real Axios client (`listEntries`, `getEntry`, `upsertEntry`, `deleteEntry`, `triggerReload`, `getAuditHistory`). Maintains in-memory state across calls within one session. Returns Axios-shaped responses (`{ data, status, headers }`) so callers see no difference.
- △ `ui/src/api/client.ts` — detect demo mode (`?demo` query OR `MODE === 'demo'`); when active, swap the exported client for the demo client. The detection is one-time at module load.
- △ `ui/vite.config.ts` — accept `--mode demo`; `isDemo = mode === 'demo'`; add a `define` so `import.meta.env.MODE` resolves correctly. Otherwise no behavioral change in prod build.

**Verification:**
- `cd ui && npm run dev` (normal mode) — unchanged behavior (calls real API; demo data is tree-shaken out)
- `cd ui && npm run dev -- --mode demo` — Vite starts; opening `localhost:5173` works without a backend; navigation works; mutations persist within the session
- `cd ui && npm run build` (prod) — bundle size delta < 5 KB (demo code tree-shaken)

**Depends:** none.

## B36 — Playwright screenshot tests

**Goal:** `npm run screenshots` from `ui/` runs Playwright against Vite-in-demo-mode and saves 10 PNGs to `website/static/img/screenshots/`.

**Files:**
- ✱ `ui/playwright.config.ts` — base URL `http://localhost:5179`, viewport 1280×800, Vite as `webServer` in demo mode, 30s timeout
- ✱ `ui/e2e/screenshots.spec.ts` — 10 test cases, one per screenshot per the spec's table
- △ `ui/package.json` — add `"screenshots": "playwright test --config playwright.config.ts"` + `"screenshots:install": "playwright install chromium"` scripts; add `@playwright/test` as a devDependency

Each test:
1. `page.goto('/?demo')` (or path-specific URL — for dialogs, navigate first then click the trigger)
2. Wait for the UI to settle (`page.locator('table').waitFor()` or similar)
3. For dialog screenshots: click the trigger button and wait for the dialog to be visible
4. `await page.screenshot({ path: 'website/static/img/screenshots/{name}.png' })`
5. For full-page screenshots (10-access-warning, 01-entries-list): pass `fullPage: true`

**Verification:**
- `cd ui && npx playwright install chromium` (one-time setup)
- `cd ui && npm run screenshots` — all 10 tests pass; 10 PNGs land in `website/static/img/screenshots/`
- Re-run produces byte-identical PNGs (determinism check)

**Depends:** B34 (output directory exists), B35 (demo mode works).

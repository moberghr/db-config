# db-config — v0.5.0 Production Hardening Spec

**Date:** 2026-05-17
**Author:** Claude (Opus 4.7) + Domagoj
**Status:** Pending approval

## Goal

Close the production-readiness gaps still hanging from v0.1.0–v0.4.0: at-rest encryption for secrets, audit log with HTTP and UI surfaces, scope-name collation consistency, and two cleanup items (UI `setTimeout` hack, `SpinWait` test patterns).

## Scope Classification

- **Type:** substantial / multi-package / multi-batch
- **Implementation path:** subagent
- **Security impact:** **medium-high** — encryption added; audit log records identity + mutation history. CLAUDE.md §0.2 needs updating after this lands (the "plaintext by default" rule changes).
- **Breaking-change risk:** YES — `IConfigStore.UpsertAsync` semantics change (now encrypts when `IsSecret=true`); audit table is a new schema migration; column collations change. Greenfield (no published NuGet), so internal-only churn.

## Out of Scope (v0.5.0)

- Audit log retention pruner (manual cleanup documented; opt-in pruner deferred to v0.6.0)
- Audit log read-events (we log mutations only — PUT/DELETE/UPSERT; GETs are not logged)
- Push-based reload (Service Broker / LISTEN-NOTIFY) — v0.6.0
- UI diff view, bulk edit, import/export — v0.6.0
- Parent/inheritance column (Option C from v0.4.0) — v0.6.0+
- KMS / Vault / cert-protected key ring extensions — abstraction is in scope; specific platform integrations are not

## Public Contract Changes

### `IConfigEncryptor` (new, in `DbConfig.Core`)

```csharp
namespace DbConfig.Core;

public interface IConfigEncryptor
{
    /// <summary>
    /// Encrypts a plaintext value. Called only for entries where IsSecret=true.
    /// Returns a stable string representation suitable for storage in nvarchar(max).
    /// </summary>
    string Protect(string plaintext);

    /// <summary>
    /// Decrypts a previously-protected value. Throws if the input is not a valid
    /// protected payload (e.g. key revoked, payload corrupted, IsSecret bit flipped).
    /// </summary>
    string Unprotect(string ciphertext);
}
```

### `DataProtectionConfigEncryptor` (new, in `DbConfig.EntityFrameworkCore`)

Default implementation wrapping ASP.NET Core Data Protection:

```csharp
public sealed class DataProtectionConfigEncryptor : IConfigEncryptor
{
    public DataProtectionConfigEncryptor(IDataProtectionProvider provider);
    public string Protect(string plaintext);
    public string Unprotect(string ciphertext);
}
```

Registered automatically by `AddDbConfig` via `TryAddSingleton<IConfigEncryptor, DataProtectionConfigEncryptor>()`. Calls `services.AddDataProtection()` if not already present (uses `TryAddSingleton` on the protection provider so consumers can pre-configure key persistence).

### `ConfigEntry` (unchanged shape; semantic change)

Field `Value` is now ciphertext when `IsSecret=true`, plaintext when `IsSecret=false`. The wire contract on `IConfigStore` returns decrypted plaintext to the caller — encryption is transparent at the store boundary. So `IConfiguration["MyKey"]` still returns the plaintext you wrote.

### `ConfigAuditEntry` record (new, in `DbConfig.Core`)

```csharp
public sealed record ConfigAuditEntry(
    Guid Id,
    string Scope,
    string Environment,
    string Key,
    string? OldValue,    // plaintext, decrypted on read
    string? NewValue,    // plaintext, decrypted on read
    bool IsSecret,
    ConfigAuditAction Action,    // Insert | Update | Delete
    DateTimeOffset ModifiedUtc,
    string? ModifiedBy);

public enum ConfigAuditAction { Insert, Update, Delete }
```

### `IConfigAuditStore` (new, in `DbConfig.Core`)

```csharp
public interface IConfigAuditStore
{
    Task<IReadOnlyList<ConfigAuditEntry>> GetHistoryAsync(
        string scope, string environment, string key, int take, CancellationToken ct);
}
```

Audit writes are NOT on this interface — they're internal, performed by `EfCoreConfigStore` in the same `SaveChangesAsync` as the mutation. The interface exposes only the read path.

### Audit table schema (new, both DB engines)

```
DbConfig_AuditEntries
  Id            uniqueidentifier   PK
  Scope       nvarchar(128)      NOT NULL    (case-sensitive collation; see Collation Fix)
  Environment   nvarchar(64)       NOT NULL    (same)
  Key           nvarchar(512)      NOT NULL    (same)
  OldValue      nvarchar(max)      NULL        (ciphertext when IsSecret=true)
  NewValue      nvarchar(max)      NULL        (ciphertext when IsSecret=true; null on Delete)
  IsSecret      bit                NOT NULL
  Action        nvarchar(16)       NOT NULL    ('Insert' | 'Update' | 'Delete')
  ModifiedUtc   datetime2          NOT NULL
  ModifiedBy    nvarchar(256)      NULL
  INDEX (Scope, Environment, Key, ModifiedUtc DESC)   -- supports history query
```

No FK to `DbConfig_Entries` (because entries can be deleted; audit must survive).

### `MapDbConfigHttp` — new endpoint

`GET /{scope}/{environment}/audit/{*key}?take=50` returns `ConfigAuditEntry[]` ordered most-recent-first. Honors existing `scopeFilter` (cross-scope audit reads → 403).

### Collation fix

`Scope`, `Environment`, `Key` columns on BOTH tables (`DbConfig_Entries` and `DbConfig_AuditEntries`) get case-sensitive binary collations:
- SQL Server: `Latin1_General_100_BIN2`
- PostgreSQL: `"C"`

Configured via `.UseCollation(...)` in `OnModelCreating`. New migration applies the collation change.

After this, `scopeFilter: "MyApp"` and `Scope='MyApp'` use the same comparison rules end-to-end. No more silent case-insensitive matches in the DB while the HTTP layer is ordinal-strict.

### `DbConfigOptions` additions

```csharp
public sealed class DbConfigOptions
{
    // existing fields unchanged
    public bool EnableAuditLog { get; set; } = true;       // NEW — opt out if desired
}
```

When `EnableAuditLog = false`, `EfCoreConfigStore` skips writing audit rows entirely (no perf cost, no table required if you don't apply the migration — but the migration still ships).

## UI Changes

- New "History" button on each row in `EntriesTable`
- Clicking opens `EntryHistoryDialog` showing recent audit entries (action, who, when, old → new value with secret values masked by default + reveal toggle)
- The dialog calls `GET /{app}/{env}/audit/{key}?take=50`
- Empty history shows "No audit history yet"

## Assumptions and Risks

| # | Item | Mitigation |
|---|---|---|
| A1 | Data Protection's default filesystem key ring is acceptable for v0.5.0 | Document `services.AddDataProtection().PersistKeysToXyz()` as a follow-up customization point |
| A2 | `IsSecret` is the authoritative flag for encryption decision | The flag drives encryption deterministically. Flipping it post-hoc returns ciphertext or fails decryption (documented in the §0.2 rewrite) |
| A3 | Audit log doesn't capture reads | We log mutations only. Read-event auditing is v0.6.0+ if a customer asks. |
| R1 | Schema migration changes collation on existing columns | Pre-1.0 NuGet → no shipped data to migrate. Migration is straightforward. |
| R2 | Audit row write doubles write traffic | Single transaction = at most 2x rows per mutation; queries unaffected. Acceptable for config-management workload. |
| R3 | Encryption adds ~4-8KB per encrypted value due to Data Protection envelope | Acceptable for config values (typically small). Documented in the project-specific rules. |
| R4 | Test fixtures may need encryption setup | `SqlServerFixture` / `PostgreSqlFixture` register a deterministic `IConfigEncryptor` for tests (so ciphertext is stable across runs). |

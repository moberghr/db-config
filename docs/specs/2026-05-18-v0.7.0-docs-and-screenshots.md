# db-config — v0.7.0 Docs Site + UI Screenshot Tests

**Date:** 2026-05-18
**Status:** Pending approval

## Goal

Ship a Docusaurus documentation site for db-config with embedded UI screenshots captured by Playwright tests against a deterministic demo mode of the React UI. Mirrors the pattern from warp (`jobly`).

## Scope Classification

- **Type:** substantial / multi-package / docs+infra
- **Implementation path:** subagent
- **Security impact:** none (docs + test infra)
- **Breaking-change risk:** none (additive — adds `website/`, `ui/src/demo/`, `ui/e2e/`; minor non-breaking edit to `ui/src/api/client.ts` to detect demo mode)

## Out of Scope (v0.7.0)

- Dark mode UI (would need a parallel `*-dark` screenshot set later)
- Search / Algolia integration in Docusaurus (use built-in local search)
- Hosting / deployment automation (we build locally; GH Pages / Netlify wiring is v0.8.0)
- Translations / i18n
- Versioned docs (single-version site for v0.x)

## Public Contract Changes

None. The runtime API surface is unchanged. The only consumer-visible additions are:

- A `website/` directory at the repo root (docs source)
- A `?demo` query parameter on the UI that activates demo data (intentionally undocumented to consumers; opt-in only via the explicit query string)

## Architecture

### `website/` (Docusaurus 3.10)

Mirrors warp's `website/` shape:

- `website/docusaurus.config.ts` — site config (title `DbConfig`, tagline, GitHub link, etc.)
- `website/sidebars.ts` — autogenerated from `docs/` folder structure
- `website/docs/` — content (see Docs Structure below)
- `website/src/` — Docusaurus theme overrides (minimal; copy warp's pattern)
- `website/static/img/screenshots/` — Playwright output target
- `website/package.json` — Docusaurus 3.10 + faster preset, same versions as warp

### Demo mode in the UI

Today the UI calls real HTTP endpoints via Axios. For deterministic screenshots, we add a demo adapter that:

1. Activates when `?demo` query string is present OR Vite is started with `--mode demo`
2. Replaces the Axios instance in `ui/src/api/client.ts` with a stub that resolves all calls against in-memory demo data
3. Demo data: `ui/src/demo/data.ts` — typed `ConfigEntry[]` + `ConfigAuditEntry[]` snapshots
4. Demo adapter: `ui/src/demo/adapter.ts` — exposes `createDemoClient()` which mimics `listEntries`, `upsertEntry`, `deleteEntry`, `getAuditHistory`, `triggerReload` against the in-memory state (writes mutate local state — survives across navigation within one session)

The hook in `client.ts` is small:

```ts
const isDemo = new URLSearchParams(window.location.search).has('demo')
    || import.meta.env.MODE === 'demo';
export const apiClient = isDemo ? createDemoClient() : createRealClient();
```

## Assumptions and Risks

| # | Item | Mitigation |
|---|---|---|
| A1 | Docusaurus 3.10 + React 19 stack matches warp's setup; no compatibility issues with Node 20+ | Direct copy of warp's `package.json` versions |
| A2 | The demo adapter's in-memory state survives within a single Playwright test session | Each test starts with a fresh page → fresh data; intentional |
| A3 | Screenshots are deterministic enough for CI (no timestamps, no random values that drift) | Demo data uses fixed `ISO8601` strings computed from `NOW - N days`; NOW is captured once per Playwright run |
| R1 | UI bundle size growth from demo data in production builds | Wrap demo imports in dynamic import gated by `?demo` check; tree-shaker drops them in prod builds |
| R2 | Playwright tests in CI without browser cache pollute screenshots with subtle font / antialiasing diffs | Use `playwright install chromium` lockstep; capture in headless mode with consistent viewport |
| R3 | Docs site goes stale relative to code | Each release cycle's docs batch (we already have one per version) updates the affected pages |

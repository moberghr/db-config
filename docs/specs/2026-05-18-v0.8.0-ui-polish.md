# db-config — v0.8.0 UI Polish Spec

**Date:** 2026-05-18
**Status:** Pending approval

## Goal

Three UI improvements to the React editor:

1. **Dark mode** — class-based Tailwind dark mode with a sun/moon toggle in the header, persisted to localStorage. Every component gets theme-aware color classes.
2. **Hierarchical tree view** — toggle between flat table and a colon-prefix grouped tree (`Stripe:Payment:Foo`, `Stripe:Payment:Bar`, `Stripe:Auth:Baz` group under `Stripe → Payment / Auth`). All row actions still available on leaves.
3. **Larger modals** — Edit / Create ~700px wide, History dialog ~900px wide, Import dialog ~800px wide. Textareas get min-height for realistic JSON / connection-string editing.

Plus a small Docusaurus tweak: the docs site theme toggle should only offer light/dark, not "system".

Screenshot regeneration: 20 PNGs total (light + dark for each of the 10 existing UI states).

## Scope Classification

- **Type:** substantial / UI-only / multi-batch
- **Implementation path:** subagent
- **Security impact:** none (visual + layout changes only)
- **Breaking-change risk:** none (additive UI features; existing layout stays as default for flat view; dark mode opt-in via toggle)

None — UI changes only. The HTTP/store/provider surfaces stay identical. The Docusaurus config tweak is internal to `website/`.

## Feature 1 — Dark mode

### Tailwind config

- Add `darkMode: 'class'` to `ui/tailwind.config.js` (or equivalent — for Tailwind 4 the syntax differs slightly; verify in implementation)
- Add a `dark` class to `<html>` based on `themeStore` state at app boot (in `main.tsx` or App)

### Theme store

- ✱ `ui/src/store/themeStore.ts` — Zustand store with `{ theme: 'light' | 'dark', setTheme(t), toggle() }`
- Persist to localStorage as `db-config-theme`
- Default: `'light'` (no system-preference detection per user request)
- On change, toggle the `dark` class on `document.documentElement`

### Header toggle

- ✱ `ui/src/components/ThemeToggle.tsx` — sun/moon icon button in the page header (next to ReloadButton)
- Click toggles theme; icon swaps to reflect current

### Component sweep

Every component touching colors needs theme-aware classes:
- `bg-white` → `bg-white dark:bg-slate-900`
- `text-gray-900` → `text-gray-900 dark:text-gray-100`
- `border-gray-200` → `border-gray-200 dark:border-slate-700`
- etc.

Files to sweep (every TSX in `ui/src/`):
- `EntriesTable.tsx`, `SecretValueCell.tsx`, `EntryHistoryDialog.tsx`, `ValueDiff.tsx`, `EditValueDialog.tsx`, `CreateEntryDialog.tsx`, `DeleteEntryDialog.tsx`, `ScopeSelector.tsx`, `ReloadButton.tsx`, `BulkActionsToolbar.tsx`, `BulkOperationDialog.tsx`, `ExportButton.tsx`, `ImportDialog.tsx`, `AccessWarningBanner.tsx`, `ViewModeToggle.tsx`
- Plus the new `ThemeToggle.tsx` and `TreeView` from Feature 2
- Plus `ui/src/components/ui/*` (button, dialog, input, textarea, checkbox, table)
- Plus `ui/src/styles/globals.css` for any global rules

The shadcn-style primitives we use are already CSS-variable-driven (the `--ifm-color-primary` style from B34 has analogs in our `globals.css`). The dark theme tokens already exist in `globals.css` per B4; the issue is that the components currently hardcode `bg-white` etc. instead of using `bg-background` (the CSS-variable-backed class).

**Approach:** prefer the semantic CSS variable classes (`bg-background`, `text-foreground`, `bg-card`, `border-border`, `text-muted-foreground`, `bg-destructive`, etc.) over hardcoded color names. This way the same component renders correctly in both themes without `dark:` prefixes everywhere.

### Docusaurus theme toggle tweak

- △ `website/docusaurus.config.ts`:
  - `themeConfig.colorMode`: `{ defaultMode: 'light', disableSwitch: false, respectPrefersColorScheme: false }`
  - Investigate whether the navbar's color-mode toggle has a 3-way option (light/dark/system) that needs disabling — Docusaurus 3.10's default is just a 2-state toggle when `respectPrefersColorScheme: false` is set, so this should be enough. Verify after change.

## Feature 2 — Hierarchical tree view

### View mode toggle

- △ `ui/src/store/scopeStore.ts` — add `listMode: 'flat' | 'tree'` (default `'flat'`), persist alongside existing scope/viewMode fields
- ✱ `ui/src/components/ListModeToggle.tsx` — segmented control: `Flat | Tree` next to the existing `ViewModeToggle` (Mine/Shared/All)

### Tree builder

- ✱ `ui/src/lib/keyTree.ts` — pure functions:
  - `buildTree(entries: ConfigEntry[]): TreeNode[]` — partitions keys by `:` separator; returns a list of root nodes; each `TreeNode` has `{ segment: string, fullPrefix: string, children: TreeNode[], entries: ConfigEntry[] }`
  - Leaf nodes (no `:` in remaining key) carry their `ConfigEntry` directly
  - Group nodes count entries in their subtree
  - Stable sort by segment name within each level
- Unit-test-style coverage if vitest is set up; otherwise rely on TS types + manual smoke

### Tree renderer

- ✱ `ui/src/components/EntriesTreeView.tsx`:
  - Recursive component rendering `TreeNode[]` as nested rows
  - Group rows show `{segment} ({count})` with a chevron (collapsed by default; click to expand)
  - Leaf rows render the same columns as `EntriesTable` (Scope, Key, Value, Modified, Modified By, History, Edit, Delete, checkbox for bulk)
  - Indentation per nesting level (~20px per level)
  - Expand-all / Collapse-all buttons at the top
  - Expansion state local to the component (NOT persisted — reset on scope change is fine)
  - Selection state still flows through `entriesStore.selectedKeys` (shared with flat view)
- △ `ui/src/pages/EntriesPage.tsx` — render `<EntriesTreeView />` when `listMode === 'tree'`; otherwise `<EntriesTable />`. Both share the same `visibleEntries` source.

## Feature 3 — Larger modals

- △ `ImportDialog.tsx` — `<Dialog size="xl">`; preview table renders without horizontal scroll

## Assumptions and Risks

| # | Item | Mitigation |
|---|---|---|
| A1 | Existing CSS uses Tailwind's `bg-white` etc. directly; semantic CSS variables are partially wired but not used consistently | The component sweep will migrate hardcoded color classes to semantic ones (`bg-background` etc.) — bigger change than just adding `dark:` variants but cleaner long-term |
| A2 | Tree view doesn't preserve expansion state across scope changes | Acceptable trade — keeps state simple; users get the default collapsed view when switching scopes |
| A3 | 20 screenshots in `website/static/img/screenshots/` doubles disk usage | ~2 MB total; negligible |
| R1 | Component sweep is high-touch (~15 files) and could miss spots | Test by toggling theme in `npm run dev -- --mode demo` and visually scanning every dialog and table state |
| R2 | Tree-view drag-and-drop or keyboard navigation is out of scope; users may expect it | Documented as v0.9.0+ candidate |
| R3 | Modal size changes could clip on small viewports | The dialog primitive should constrain `max-w-[90vw] max-h-[90vh]` regardless of size; verify |

# v0.11.0 — React-rendered built-in login

**Date:** 2026-05-19
**Status:** Shipped

## Summary

Refactor the built-in cookie login from a server-rendered HTML form
(`BuiltInLoginEndpoints.cs` writing inline HTML) to a React-rendered
`<LoginPage>` component in the SPA bundle. Matches sister project Warp's
architecture and unifies the visual language of the entire UI.

## Why

In v0.10.x the login form lived in C# (`BuildLoginPage`), embedding inline
CSS in a single `<style>` block. It worked, but:

- Dark mode used the OS-level `prefers-color-scheme` media query, not the
  app's per-user theme toggle, so a user who manually picked dark mode in
  the dashboard would still see a light login form.
- Screenshot pipeline required a hand-maintained `login-form.html` fixture
  that mirrored the C# output byte-for-byte (drift risk).
- Visual primitives diverged: the dashboard uses shadcn's Button + Input
  with `bg-card`, `text-foreground`, `border-input` tokens; the login form
  used hand-rolled CSS with hex values.

Warp's architecture solves these in one move: the SPA serves itself for
`/login`, reads `window.dbConfig.hasBuiltInLogin`, checks `/api/auth/status`
on mount, and renders its own login component when needed.

## Architecture

```
Browser GET /admin/dbconfig/login (Accept: text/html)
  ↓
DbConfigUiAuthFilter:
  • not /api/auth/* → run auth check
  • not authorized → browser request + built-in login → next() (serve SPA)
  ↓
EmbeddedStaticFileMiddleware serves index.html with injected:
  <meta name="db-config-api-prefix" content="/api/dbconfig">
  <script>window.dbConfig = { apiPrefix: "/api/dbconfig", hasBuiltInLogin: true };</script>
  ↓
SPA loads, App.tsx checks fetchAuthStatus()
  → GET /admin/dbconfig/api/auth/status (allowed unauthenticated by the filter)
  → { authenticated: false, hasBuiltInLogin: true }
  ↓
<LoginPage> mounts. User submits.
  → POST /admin/dbconfig/api/auth/login { username, password }
  → 200 { ok: true } + Set-Cookie
  ↓
App re-checks status → authenticated → mounts <EntriesPage>.
```

## Backend changes

**`BuiltInLoginEndpoints.cs`** (full rewrite, server-rendered HTML deleted):

- `HandleAuthStatusAsync` — returns `{ authenticated, hasBuiltInLogin, username? }`.
  Bypassed by the auth filter so the SPA can probe pre-login.
- `HandleLoginPostAsync` — JSON in, JSON out. 200 with cookie on success;
  401 `{ error }` on failure. No form parsing, no redirects.
- `HandleLogoutPostAsync` — clears cookie, returns 200 `{ ok: true }`.
- `BuildLoginPage` (HTML rendering), `SanitizeReturnUrl`, `HandleLoginGetAsync`
  — DELETED. `/login` is now a SPA route served by the catch-all.

**`EndpointRouteBuilderExtensions.cs`** — registers the new JSON endpoints
under `/api/auth/*` on the UI route group. The HTTP API's catch-all
(`/{appName}/{environment}/{*key}`) requires 3+ segments after `/api/`, so
auth paths (2 segments) don't collide with `MapDbConfigAdmin`'s API.

**`DbConfigUiAuthFilter.cs`** — auth check semantics for unauthorized
browser navigations changed from "302 to `/login`" to "let the SPA shell
render so React can decide". `/api/auth/*` is the new always-reachable
path-prefix exemption (replaces the old `/login` + `/logout` exemption).

**`EmbeddedStaticFileMiddleware.cs`** — adds `hasBuiltInLogin` constructor
parameter, injects `window.dbConfig = { apiPrefix, hasBuiltInLogin }` into
`index.html`.

## Frontend changes

- `ui/src/api/auth.ts` — new auth helper. `fetchAuthStatus`, `login`,
  `logout`. Demo-mode short-circuits with a `?demoLoggedOut` query string
  that flips the simulated auth state to `false` so screenshot tests can
  capture the LoginPage.
- `ui/src/pages/LoginPage.tsx` — new React component. Uses shared
  `<Button>`, `<Input>`, `<ThemeToggle>` — dark mode works via the
  `.dark` class on `<html>` like the rest of the UI.
- `ui/src/components/SignOutButton.tsx` — new. Renders a `LogOut` icon
  button in the header; calls `logout()` then re-runs the auth check.
- `ui/src/App.tsx` — adds an auth gate: `checking` → empty shell;
  `login` → `<LoginPage>`; `authenticated` → mounts `<TabbedApp>` and
  passes `<SignOutButton>` via the new `headerExtras` slot to both pages.
- `ui/src/pages/EntriesPage.tsx`, `ui/src/pages/AuditLogPage.tsx` — accept
  optional `headerExtras` prop and render it next to `<ThemeToggle>`.

## Demo mode

The demo adapter short-circuits the auth API:
- `fetchAuthStatus` returns `{ authenticated: true, hasBuiltInLogin: true, username: "demo-user" }` by default.
- Appending `?demoLoggedOut` flips the initial state to `false`. The SPA
  mounts `<LoginPage>`. The screenshot test for the login page uses this.
- `login()` flips the state back to authenticated; `logout()` flips it
  back to unauthenticated.

## Screenshot pipeline

- `ui/e2e/fixtures/login-form.html` — DELETED.
- `ui/e2e/screenshots.spec.ts` — `15-login-form{,-dark}` now navigates to
  `/?demo&demoLoggedOut` and captures the real React form. No file:// load.

## Test impact

- `BuiltInLoginTests.cs` — rewritten. Old tests: 5 (Anonymous redirect,
  Login form GET, Login POST happy + invalid + open-redirect). New tests:
  7 (Login GET serves SPA, Login POST JSON happy + 401, Logout, AuthStatus
  unauthenticated + authenticated, Browser navigation serves SPA shell).
- `MapDbConfigAdminTests.UnifiedMount_UiAndApi_BothUseSameCookie` —
  updated to POST JSON.
- `MapDbConfigAdminTests.UnifiedMount_WithoutLogin_BothRedirect` —
  renamed to `..._BrowserGetsSpaShellApiGets401`. Asserts SPA HTML with
  `window.dbConfig` script, not a 302 to `/login`.
- Net unit-test count: 248 → 250 (+2).

## Backwards compatibility

Consumer-facing API unchanged. `opts.UseBuiltInLogin<MyValidator>()` works
exactly as before. The internal endpoint paths changed
(`/login` POST → `/api/auth/login` POST etc.) but those paths were not
documented as a public contract — the documented surface is the C# API.

Cookie name, payload format, signing scheme, and Path scoping are
unchanged. Existing cookies issued by v0.10.x continue to validate.

## Risks

- Hosts that bookmark or document the OLD `POST /admin/dbconfig/login`
  endpoint must update integrations. This is the explicit breaking change;
  the JSON contract is now the public surface.
- The SPA bundle gains ~200 lines of auth-flow code. Bundle size impact
  is negligible (LoginPage uses already-loaded shared primitives).

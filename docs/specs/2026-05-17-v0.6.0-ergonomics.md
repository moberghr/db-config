# db-config — v0.6.0 Ergonomics Spec

**Date:** 2026-05-17
**Status:** Pending approval

## Goal

Three independent quality-of-life improvements: opt-in read auditing for compliance, UI feature deepening (diff/bulk-edit/import-export), and removing the instance-only restriction on `IConfigEncryptor` registration.

## Scope Classification

- **Type:** substantial / multi-package / multi-batch
- **Implementation path:** subagent
- **Security impact:** **low** — read auditing adds audit rows but no privilege change; encryption stays equivalent; UI features are read-mostly with confirmation gates on bulk ops
- **Breaking-change risk:** YES on the encryptor side (consumers using the v0.5.0 instance-only pattern still work, but the recommended pattern shifts). Read-audit adds a `Read` value to `ConfigAuditAction` enum — additive, non-breaking.

## Out of Scope (v0.6.0)

- Audit retention pruner (user explicitly excluded; deferred to v0.7.0+)
- Parent/inheritance scope column (deferred — no concrete consumer need yet)
- Visibility tags (same)
- Multi-scope `AddDbConfig` per host (same)
- Push-based reload, non-EF stores (explicitly out of scope for the foreseeable future)

## Feature 1 — Read auditing (opt-in)

### `DbConfigOptions` addition

```csharp
/// <summary>
/// When true, HTTP GET endpoints (list + single + audit history) write audit rows.
/// Default false to avoid noise for compliance-relaxed deployments.
/// Read audit rows carry Action=Read, OldValue=null, NewValue=null.
/// </summary>
public bool AuditReads { get; set; } = false;
```

### `ConfigAuditAction` enum

```csharp
public enum ConfigAuditAction { Insert, Update, Delete, Read }   // Read is NEW
```

### HTTP endpoints behavior

When `AuditReads = true`:
- `GET /{app}/{env}` (list) → one audit row per request with `Key="*"` (sentinel for "list-all")
- `GET /{app}/{env}/{*key}` (single) → one audit row with the requested key
- `GET /{app}/{env}/audit/{*key}` (history endpoint) does NOT generate read audit (avoid infinite recursion / noise)

OldValue/NewValue both null. ModifiedUtc = read timestamp. ModifiedBy = `httpContext.User?.Identity?.Name`.

### Audit row inserts use the existing `IConfigAuditStore.WriteAsync` path

The current `IConfigAuditStore` interface is **read-only** (GetHistoryAsync). For v0.6.0 we add:

```csharp
public interface IConfigAuditStore
{
    Task<IReadOnlyList<ConfigAuditEntry>> GetHistoryAsync(...);   // existing

    /// <summary>
    /// Writes an audit row. Called by HTTP endpoints when AuditReads=true,
    /// and by EfCoreConfigStore for in-transaction mutation audits (which use
    /// the EF DbContext directly — this overload is for out-of-transaction writes
    /// like read audits where the DB write is fire-and-forget).
    /// </summary>
    Task WriteAsync(ConfigAuditEntry entry, CancellationToken ct);   // NEW
}
```

Read audits are written fire-and-forget (NOT in the request transaction — that would mean every GET acquires a DB write lock, killing read throughput). A failure to write a read-audit logs a warning; the GET still returns success. Mutation audits remain in-transaction.

## Feature 2 — UI features

### 2A. Diff view in `EntryHistoryDialog`

Each row in the history table gets a "Compare to previous" toggle. When active, the row renders an inline side-by-side diff:

- Left column: OldValue (decrypted if needed)
- Right column: NewValue
- Color-coded character-level diff (added: green, removed: red, unchanged: grey)
- For values containing JSON, parse and pretty-print before diffing for readable output

Use a small TypeScript diff library (e.g. `diff` from npm) or roll a simple LCS algorithm — pick whichever is smaller.

### 2B. Bulk edit

In `EntriesTable`:
- Each row gains a checkbox in a new leftmost column
- Header has a "select all" checkbox
- When ≥1 row is selected, a `BulkActionsToolbar` appears above the table with:
  - "Toggle IsSecret" — flips the secret flag on all selected entries (warns about implications)
  - "Move to scope" — opens a scope picker; moves entries to the chosen scope (deletes from current + inserts in target; uses existing upsert/delete endpoints)
  - "Delete selected" — confirmation dialog, then loops deletes
- All bulk operations show progress + per-item error reporting

### 2C. Import / Export

New "File" menu (or two buttons in `EntriesPage` toolbar):

**Export:**
- Click → fetch all entries for the current scope (respecting view mode)
- Serialize to **appsettings.json**-shape (hierarchical: `Section:Sub:Key` → `{Section: {Sub: {Key: ...}}}`)
- Optionally include a sidecar `__dbconfig_metadata` block with `isSecret` flags + `modifiedUtc` + `modifiedBy` per leaf
- Trigger browser download

**Import:**
- Click → file picker (.json)
- Parse client-side; show a preview table of entries to be imported
- Collision policy selector: `Overwrite | Skip existing | Error on collision`
- "Import" button → loops upserts via existing PUT endpoint; progress bar; final summary

### UI changes are entirely client-side; no new HTTP endpoints needed.

## Feature 3 — Type-mapped `IConfigEncryptor`

### Today (v0.5.0)

```csharp
// REQUIRED
services.AddSingleton<IConfigEncryptor>(new MyAzureKeyVaultEncryptor(client, options));

// THROWS
services.AddSingleton<IConfigEncryptor, MyAzureKeyVaultEncryptor>();
```

### v0.6.0 target

Both work. Type-mapped registrations get DI-resolved encryptor dependencies (IKeyClient, IOptions, ILogger).

### Implementation

The polling-side store's encryption is the constraint — it needs an encryptor at construction time, but the host SP isn't built yet.

**Solution:** defer polling-side decryption until the host has built. The polling provider stores raw values (potentially ciphertext) in its internal dictionary. `Get(string key)` decrypts lazily using a `Lazy<IConfigEncryptor>` whose factory resolves from the host SP. The first call to `Get` for a secret AFTER the host has built triggers resolution.

**Constraint surfaced to consumers:** reading secret values BEFORE `app.Build()` returns is not supported. Reading non-secret values is unaffected.

### Polling-side store changes

- `EfCoreConfigStore` (polling instance) stores raw values without decryption. The encryptor field is nullable; when null, returned values match what was stored (consumers see ciphertext for IsSecret rows).
- `DbConfigConfigurationProvider` exposes a `SetEncryptor(IConfigEncryptor)` internal method. An `IHostedService` registered by `AddDbConfig` (a new `DbConfigEncryptorActivator`) runs `StartAsync` to resolve `IConfigEncryptor` from host SP and call `provider.SetEncryptor(...)`. Hosted services run AFTER the host is built, so the SP is ready.
- The provider's `Get(key)` override checks: if value is null or non-secret, return as-is. If IsSecret and encryptor is set, decrypt. If IsSecret and encryptor NOT yet set (called too early in startup), throw `InvalidOperationException` with a clear message: "Cannot read secret value 'X' before host.Build() has returned. Move this read to a request handler, hosted service, or `OnStarted` callback."

### Backward compatibility

The instance-registration path STILL WORKS — `AddDbConfig` checks for an `ImplementationInstance` first (as v0.5.0 did). If found, polls and HTTP share that instance, and the activator hosted service is a no-op. If only a type-mapped registration exists, the activator resolves it post-build.

## Assumptions and Risks

| # | Item | Mitigation |
|---|---|---|
| A1 | Read audits at default-off avoid the perf cost for non-compliance shops | Default `AuditReads = false`; opt-in only |
| A2 | Fire-and-forget read audits are acceptable (some loss possible on crash) | Documented as the trade vs. in-transaction; consumers needing zero-loss audit reads can layer their own middleware |
| A3 | UI bulk operations use existing endpoints in a loop (no new bulk endpoints) | Simpler to ship; acceptable perf for human-paced editor (50 entries × small ms) |
| R1 | Type-mapped encryptor decryption deferred until post-build means startup-time secret reads fail | Documented as a clear runtime error; the common case (read in request handler) is unaffected |
| R2 | The `Read` audit action grows the audit table much faster than mutations | Default-off; consumers who enable it accept the volume; retention SQL covers it |
| R3 | Diff view's character-level diff on large JSON values is computationally heavy in the browser | Limit diff to ≤ 100KB values; show a "Value too large to diff" message above that |
| R4 | Import collision policy "Error on collision" could leave partial state if some imports succeeded before the conflict | Document; consumers can use Overwrite for clean re-imports |

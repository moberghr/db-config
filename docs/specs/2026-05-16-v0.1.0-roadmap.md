# db-config — v0.1.0 Roadmap Spec

**Date:** 2026-05-16
**Author:** Claude (Opus 4.7) + Domagoj
**Status:** Pending approval

## Goal

Ship `Moberg.DbConfig.*` v1 — a database-backed `IConfiguration` provider for .NET 8 with an embedded React editor UI. Behave like a secrets-manager replacement that lives in the consumer's own database. No external dependency.

## Scope Classification

- **Type:** substantial / multi-package / multi-batch
- **Implementation path:** subagent (per `implement` skill's fork rules: >= 3 batches, >= 6 files, security_impact = medium)
- **Security impact:** medium — endpoints expose secret values, host-supplied auth is the only gate; at-rest encryption explicitly out of scope (DB TDE / column encryption is the consumer's responsibility)
- **Breaking-change risk:** N/A (greenfield)

## Out of Scope (v1)

- At-rest encryption of values (deferred — relies on DB TDE / column encryption; CLAUDE.md §0.2)
- Audit log table (only inline `ModifiedUtc` / `ModifiedBy` columns; no separate history)
- Multi-tenancy beyond the `(Scope, Environment)` composite key
- Push notifications for change events (polling only; no SQL notifications / LISTEN-NOTIFY)
- Import/export to JSON or appsettings format
- Diff view / history in the UI
- Bulk edit
- Role-based field-level permissions (auth is all-or-nothing per the host's policy)
- Schema migration tool for the consumer (we ship raw EF migrations; consumer chooses when to apply)

|---|---|---|---|

## Data Model

Table name (default, overridable): `DbConfig_Entries`

```
DbConfig_Entries
  Id            uniqueidentifier   PK
  Scope       nvarchar(128)      NOT NULL
  Environment   nvarchar(64)       NOT NULL
  Key           nvarchar(512)      NOT NULL
  Value         nvarchar(max)      NULL
  IsSecret      bit                NOT NULL  default 0
  ModifiedUtc   datetime2          NOT NULL
  ModifiedBy    nvarchar(256)      NULL
  UNIQUE (Scope, Environment, Key)
  INDEX (Scope, Environment, ModifiedUtc DESC)   -- supports change polling
```

PostgreSQL equivalents: `uuid`, `text` (no length cap), `boolean`, `timestamptz`.

## Reload Semantics

- `DbConfigConfigurationProvider` starts a `Timer`-driven loop on `Load()`.
- Each tick: `GetLatestModifiedUtcAsync`. If the watermark advanced, `GetAllAsync` + replace internal dictionary + `OnReload()` (fires the `IChangeToken`).
- `POST /reload` triggers an immediate tick via an in-process signal.
- Failures during reload: log warning, keep previous values, retry on next tick. **Never** throw from the timer callback.

## Test Manifest

Each batch carries its own tests. The full suite must pass on both SQL Server and PostgreSQL via Testcontainers. Categories: `Unit`, `SqlServer`, `PostgreSql`.

Specific must-have tests:

- Hierarchical key flattening: `{ "Section": { "Sub": "v" } }` → `Section:Sub` (round-trips via `IConfiguration`)
- Polling reload: write via store → wait one interval → `IConfiguration[key]` returns new value
- Change token: subscribe via `IOptionsMonitor<T>` → write → callback fires within 2× interval
- Reload failure resilience: store throws → previous values intact → next successful tick recovers
- Endpoint auth composition: handler-level `[Authorize]` honored when host applies `RequireAuthorization("Policy")`
- Secret flag: stored values with `IsSecret=true` returned over API (UI masks; API does not)
- Concurrent writes: two upserts to same `(App, Env, Key)` last-writer-wins (no exception)
- Both DB engines: every store-touching test runs on MSSQL **and** PG fixtures

## Assumptions and Risks

| # | Assumption / Risk | Mitigation |
|---|---|---|
| A1 | Consumer's DB has spare capacity for polling (every 30s, single row read by default) | Default interval 30s, documented as tunable; query uses indexed watermark |
| A2 | Consumer trusts everyone with DB access to read all secrets | Explicit in README, package description, and UI banner; CLAUDE.md §0.2 |
| A3 | EF Core 8.0.11 stable on both Npgsql and MSSQL providers | Pinned versions; integration tests run on both engines |
| A4 | `[Authorize]` metadata surfacing works the same way warp uses it | Mirroring `Warp.Http/EndpointRouteBuilderExtensions.cs:80-91` exactly |
| A5 | React UI fits in <300 KB gzipped (acceptable embedded-NuGet size) | Vite tree-shake + no chart/diagram libs |
| A6 | Polling-only reload acceptable for v1 (push deferred) | Decided 2026-05-16; SQL Server Service Broker / PG LISTEN-NOTIFY scoped to v2 |
| R1 | First-load failure when DB unreachable could brick app startup | Provider surfaces `InvalidOperationException` with redacted message; consumer documents the dependency |
| R2 | Race between UI upsert and polling reload could show stale values briefly | `POST /reload` after every mutation; UI awaits the round-trip before refreshing |
| R3 | Embedded React bundle increases NuGet size noticeably | Acceptable for editor convenience; can ship as separate package later if pressure |

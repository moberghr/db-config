# db-config — v0.4.0 Shared Scopes Spec

**Date:** 2026-05-17
**Author:** Claude (Opus 4.7) + Domagoj
**Status:** Pending approval

## Goal

Add cross-app scope sharing. An app can pull config from one or more "shared" scopes in addition to its own, with explicit precedence ordering. Own-scope values override shared ones. Use case: a platform team owns `Shared` and `PlatformDefaults`; each application reads those plus its own keys.

## Scope Classification

- **Type:** substantial / multi-batch
- **Implementation path:** subagent
- **Security impact:** **low-medium** — write authorization for shared scopes is the host's responsibility, but we ship a new `scopeFilter` overload on `MapDbConfigHttp` so the host can compose per-scope policies
- **Breaking-change risk:** YES — `IConfigStore` gains `GetAllScopedAsync` and `GetLatestModifiedUtcScopedAsync` as required methods. Greenfield, no published consumers, so this is fine.

## Design — Option B (Explicit `IncludeScopes`)

```csharp
builder.AddDbConfig(b =>
{
    b.UseSqlServer(connStr);
    b.Options.Scope = "PaymentService";
    b.Options.Environment = "Prod";
    b.Options.IncludeScopes = ["PlatformDefaults", "Shared"];
    // Precedence (lowest → highest): PlatformDefaults < Shared < PaymentService
    // Own scope (Scope) is always last and wins ties.
});
```

The polling provider issues `SELECT … WHERE Scope IN ('PlatformDefaults','Shared','PaymentService') AND Environment='Prod'`. It merges entries with explicit precedence: walk `IncludeScopes` lowest-precedence-first, then `Scope` last, applying each scope's entries on top. Last-writer-wins per key.

**Watermark query** covers all scopes too:
`SELECT MAX(ModifiedUtc) FROM DbConfig_Entries WHERE Scope IN (…) AND Environment = @env`.

A change in *any* included scope advances the watermark and triggers reload — that's the desired behavior so platform-side edits propagate to all consumers within one poll interval.

## Out of Scope

- Parent/inheritance column (Option C — rejected for v0.4.0; revisit if hierarchical needs emerge)
- Visibility tags (Option D — rejected as more complex without a concrete use case yet)
- Cross-environment sharing (`PaymentService/Prod` including `Shared/Staging`) — environment stays a hard isolation boundary
- Automatic shared-scope discovery (no "scan all Scopes" feature)
- At-rest encryption (still v0.5.0+)

## Public Contract Changes

### `DbConfigOptions`

```csharp
public sealed class DbConfigOptions
{
    public string Scope { get; set; } = "";
    public string Environment { get; set; } = "";
    public TimeSpan ReloadInterval { get; set; } = TimeSpan.FromSeconds(30);

    /// <summary>
    /// Additional Scope scopes to include in the polling provider's reads, ordered
    /// lowest-precedence-first. The configured <see cref="Scope"/> is always read with
    /// highest precedence (last-writer-wins per key). Empty by default.
    /// </summary>
    public IReadOnlyList<string> IncludeScopes { get; set; } = Array.Empty<string>();
}
```

### `IConfigStore` (breaking — adds two required methods)

```csharp
public interface IConfigStore
{
    // Existing — unchanged
    Task<IReadOnlyList<ConfigEntry>> GetAllAsync(string scope, string environment, CancellationToken ct);
    Task<ConfigEntry?> GetAsync(string scope, string environment, string key, CancellationToken ct);
    Task<DateTimeOffset?> GetLatestModifiedUtcAsync(string scope, string environment, CancellationToken ct);
    Task UpsertAsync(ConfigEntry entry, CancellationToken ct);
    Task DeleteAsync(string scope, string environment, string key, CancellationToken ct);

    // NEW — multi-scope variants
    Task<IReadOnlyList<ConfigEntry>> GetAllScopedAsync(
        IReadOnlyList<string> scopes, string environment, CancellationToken ct);

    Task<DateTimeOffset?> GetLatestModifiedUtcScopedAsync(
        IReadOnlyList<string> scopes, string environment, CancellationToken ct);
}
```

### `ConfigEntry` (unchanged)

Already carries `Scope` — that doubles as the "source scope" field for the API and UI to display.

### HTTP API additions

`GET /{scope}/{environment}` — unchanged shape; new optional query string:
- `?includeScopes=Shared,PlatformDefaults` — server merges the listed scopes with the path's `{scope}` (precedence: path app wins). Returns merged entries with their `Scope` indicating source.

New endpoint:
- `GET /{scope}/{environment}/effective` — returns the merged view that would be visible to the polling provider, given the *server-side configured* `IncludeScopes` for this app. The server config of include-scopes lives in `DbConfigOptions` — exposed read-only via a new minimal endpoint or inferred from the configured options. (Alternatively: just use the query-string form. Pick whichever is simpler — see plan.)

### `MapDbConfigHttp` overload

```csharp
public static RouteGroupBuilder MapDbConfigHttp(
    this IEndpointRouteBuilder endpoints,
    string prefix = "/api/dbconfig",
    string? scopeFilter = null);
```

When `scopeFilter` is non-null, all endpoints under that group enforce `{scope} == scopeFilter` (returns 403 / 404 otherwise). Lets the host compose multiple groups with different policies:

```csharp
// App-team writes — only own scope
app.MapDbConfigHttp("/api/dbconfig", scopeFilter: "PaymentService")
   .RequireAuthorization("AppTeamAdmin");

// Platform-team writes — only Shared scope
app.MapDbConfigHttp("/api/dbconfig-shared", scopeFilter: "Shared")
   .RequireAuthorization("PlatformAdmin");
```

## UI Changes

- Scope badge column in `EntriesTable` showing each row's `Scope`
- "View" toggle: `Mine` (own scope only) / `Shared` (just shared scopes) / `All` (merged)
- Edit/Delete buttons disabled on rows where `entry.Scope != currentScope` — UX guard; the actual write goes to that row's scope and would be rejected by `scopeFilter` if mismatched
- New entry dialog asks which scope to write to (defaults to current) — disabled if `scopeFilter` is set

## Assumptions and Risks

| # | Item | Mitigation |
|---|---|---|
| A1 | Most apps will have ≤3 scopes; IN clause stays cheap | Default empty `IncludeScopes`; query plan still uses the `(Scope, Environment, ModifiedUtc)` index |
| A2 | Shared scopes are conventional (`Shared`, `PlatformDefaults`), not reserved | No magic names; consumer picks naming |
| R1 | Bigger result set if a consumer lists many scopes | Documented in README; if it ever becomes a problem we add per-scope partial materialization |
| R2 | The polling provider's watermark covers all included scopes — platform-side edits poll-trigger every consumer of `Shared` simultaneously | Acceptable; the reload signal already broadcasts to all in-process subscribers |
| R3 | The `scopeFilter` overload makes the API surface bigger | Optional parameter; default is unchanged; opt-in for platform/app split |

## Goal

Pay down the architecture-review findings deferred from v0.1.0. Five batches: a targeted single-key read, a two-call DI redesign, extraction of `Moberg.DbConfig.EntityFrameworkCore` from Core, provider-specific exception detection, and a domain-rules rewrite. No new user-facing features; pure architectural cleanup.

- **Type:** substantial / multi-package / multi-batch

## Public Contracts (target shape)

### Two-call DI

```csharp
// Step 1 — host DI (lambda lives here; services + options registered into host)
builder.Services.AddDbConfig(b =>
{
    b.Options.Scope = "MyApp";
    b.Options.Environment = builder.Environment.EnvironmentName;
    b.Options.ReloadInterval = TimeSpan.FromSeconds(30);
    b.UseSqlServer(connStr); // or b.UsePostgreSql(connStr) — extension on DbConfigBuilder
});

// Step 2 — configuration source (no lambda; reads options + services from host DI)
builder.Configuration.AddDbConfig();
```

How `AddDbConfig()` on `IConfigurationBuilder` finds the services: the `Services.AddDbConfig(...)` call stashes the configured `DbConfigBuilder` (and a service-provider snapshot) in a static `ConditionalWeakTable<IServiceCollection, ...>` indexed by the host `IServiceCollection`. Then the configuration extension walks the candidate service collections in `builder.Properties` (ASP.NET Core puts `builder.Services` there) or accepts an explicit overload `AddDbConfig(IServiceCollection services)` for hosts that don't expose Properties.

If that's too implicit, the explicit overload is mandatory:
```csharp
builder.Configuration.AddDbConfig(builder.Services);
```

The implementer subagent will pick the simpler shape (likely the explicit overload) and document the choice. The "magic" properties-walk is a deviation worth flagging.

### `IConfigStore.GetAsync`

```csharp
public interface IConfigStore
{
    Task<IReadOnlyList<ConfigEntry>> GetAllAsync(string scope, string env, CancellationToken ct);
    Task<ConfigEntry?> GetAsync(string scope, string env, string key, CancellationToken ct); // NEW
    Task<DateTimeOffset?> GetLatestModifiedUtcAsync(string scope, string env, CancellationToken ct);
    Task UpsertAsync(ConfigEntry entry, CancellationToken ct);
    Task DeleteAsync(string scope, string env, string key, CancellationToken ct);
}
```

`EfCoreConfigStore.GetAsync` issues `WHERE Scope = @a AND Environment = @e AND Key = @k` + `Select` projection + `FirstOrDefaultAsync`. `InMemoryConfigStore` filters its dictionary directly. `GetEntryEndpoint` switches from `GetAllAsync().FirstOrDefault()` to `GetAsync()`.

### `IUniqueConstraintDetector`

```csharp
namespace DbConfig.EntityFrameworkCore;

public interface IUniqueConstraintDetector
{
    bool IsUniqueConstraintViolation(DbUpdateException exception);
}
```

`EfCoreConfigStore.UpsertAsync` takes `IUniqueConstraintDetector` via constructor; Core has no more string-matching against provider exception types. Each provider package ships its implementation:

```csharp
namespace DbConfig.Provider.SqlServer;
public sealed class SqlServerUniqueConstraintDetector : IUniqueConstraintDetector { ... } // checks SqlException.Number == 2627 || 2601

namespace DbConfig.Provider.PostgreSql;
public sealed class PostgreSqlUniqueConstraintDetector : IUniqueConstraintDetector { ... } // checks PostgresException.SqlState == "23505"
```

`UseSqlServer` and `UsePostgreSql` register their detector in `IServiceCollection`. `EfCoreConfigStore` resolves it from the host DI.

## Assumptions and Risks

| # | Assumption / Risk | Mitigation |
|---|---|---|
| A1 | Two-call DI works in non-Web hosts (GenericHost worker services) | The shape mirrors how AspNetCore configuration sources commonly work; explicit `IServiceCollection` overload makes it portable |
| A2 | Namespace rename only affects internal consumers | Confirmed greenfield (no published NuGet); demo + tests + ui/api/client.ts are the only consumers — all owned by us |
| A3 | EF Core 8 hand-written migrations still resolve correctly after the DbContext moves to a new assembly | Migrations stay in provider assemblies (already configured via `MigrationsAssembly`); DbContext factory references work across assemblies |
| R1 | The "find services from configuration builder" trick (Properties walk) may not work in non-Web hosts | Fall back to explicit overload; the implementer is told to prefer explicit over magic |
| R2 | Test churn could mask a real regression | Run the full 65-test baseline before each batch; only proceed if green |
| R3 | The detector resolution requires the provider's `Use*` call to register the detector BEFORE `EfCoreConfigStore` is resolved | Use TryAddSingleton with the detector; document the ordering in `UseEntityFrameworkCore` XML doc |

# v0.11.1 — IConfigStore convenience overloads

**Date:** 2026-05-20
**Status:** Shipped

## Summary

Add six ergonomic overloads to `IConfigStore` so consumer code does not have to
pass `scope`/`environment` on every call, and can read typed POCOs for any
tenant. Backwards-compatible — all existing methods stay unchanged.

## Why

Up to v0.11.0 a consumer reading config explicitly through `IConfigStore`
(admin endpoints, background jobs, cross-tenant diagnostic surfaces) had to
write:

```csharp
var entry = await store.GetForTenantAsync(
    options.Value.Scope, options.Value.Environment, "Acme", "Stripe:ApiKey", ct);
```

The Scope and Environment are already known to the host — they live in the
`DbConfigOptions` singleton. Passing them on every call is boilerplate that
adds nothing to readability and invites bugs (typo in `Scope` → silent empty
read). The same goes for the current-tenant case: the `ITenantResolver`
registered by the host is already DI-available; consumers should not have to
re-resolve it manually.

Typed binds were not supported at all on the store layer — consumers had to
fetch raw entries, build an `IConfigurationRoot` themselves, and call
`Bind<T>` manually.

## What changes

### New overloads on `IConfigStore`

| Overload | Source of Scope/Env | Tenant id |
|---|---|---|
| `GetAsync(string key, ct)` | `DbConfigOptions` | `ITenantResolver.Resolve()` or global |
| `GetAllAsync(ct)` | `DbConfigOptions` | `ITenantResolver.Resolve()` or global |
| `GetForTenantAsync(string tenantId, string key, ct)` | `DbConfigOptions` | explicit |
| `GetAllForTenantAsync(string tenantId, ct)` | `DbConfigOptions` | explicit |
| `GetAsync<T>(ct)` where `T : class, new()` | `DbConfigOptions` | `ITenantResolver.Resolve()` or global |
| `GetForTenantAsync<T>(string tenantId, ct)` where `T : class, new()` | `DbConfigOptions` | explicit |

All six are default interface methods that throw `NotSupportedException` by
default — custom non-EF `IConfigStore` implementations that don't maintain
ambient state continue to compile and fail loud only if a consumer calls the
convenience overload. Both built-in stores (`EfCoreConfigStore` and
`InMemoryConfigStore`) override them.

### Typed bind semantics

Section name is `typeof(T).Name` **verbatim** — no suffix stripping. For
`StripeOptions`, the binder reads keys prefixed with `"StripeOptions:"`. This
is intentional: implicit suffix stripping (`Options` → drop) silently breaks
when a type is renamed.

Merge rule: global layer (`TenantId = ""`) is read first; tenant layer is
overlaid; tenant wins on keys present in both. Secrets are decrypted before
the POCO is bound — the caller gets plaintext.

### Constructor changes

Both store implementations gain an optional DI-friendly constructor that takes
`DbConfigOptions` and `ITenantResolver?`. Existing constructors are preserved
so all existing test sites compile unchanged. The DI registration in
`AddDbConfig` uses an explicit factory lambda to wire the new constructor for
the HTTP-side store.

Polling-side store is constructed with the same options instance but
`tenantResolver: null` — it is internal-use only; consumer code uses the
HTTP-side `IConfigStore` from DI which has the resolver injected.

## Non-goals

- Custom section names (e.g. `[ConfigSection("Stripe")]` attribute). Use the
  explicit `(scope, env)` overloads with `IConfiguration.Bind` directly when
  you need a section name that differs from the type name.
- Caching. The convenience overloads are thin wrappers over the existing
  explicit-arg methods; cache invalidation and hot reload remain the job of
  `IConfiguration` / `IOptionsSnapshot<T>`.
- Read auditing on programmatic reads. `IConfigStore` calls bypass the HTTP
  endpoints and therefore do not produce read-audit rows when
  `DbConfigOptions.AuditReads = true`. The audit log captures the HTTP API
  surface; consumers wanting full coverage of programmatic reads must layer
  their own logging at the store seam.

## Custom `IConfigStore` callout

If you implement your own `IConfigStore`, you'll want to override the new
convenience methods (`GetAsync(key)`, `GetAllAsync()`, `GetForTenantAsync<T>`,
etc.) or accept `NotSupportedException` at runtime when consumers call them.
The defaults throw with a clear message pointing to the explicit-app/env
equivalents. The explicit `(scope, environment, ...)` methods remain
required and unchanged — existing custom stores keep compiling without any
work.

## Post-release review fixes (folded into 0.11.1 tag)

The initial 0.11.1 implementation shipped with a few sharp edges that were
caught in review and fixed before the tag was pushed:

- **Targeted query path.** `BindTypedAsync<T>` used to issue two full-scope
  reads (`GetAllAsync` + `GetAllForTenantAsync`) and then filter the section
  prefix in memory. On large config tables that's wasteful — every typed
  bind scanned every key. The implementation now routes through
  `QueryAsync` with `keyPrefix = "<TypeName>:"` so the database does the
  filtering. The HTTP layer's `take` cap (10 000) stays out of this path;
  the store accepts `int.MaxValue`.
- **Generic types.** `typeof(MyGeneric<int>).Name` is `"MyGeneric\`1"` — the
  raw value would never match a real DB key. The CLR arity suffix is now
  stripped, so `MyGeneric<int>` binds from `MyGeneric:`. A new helper
  `TypedSectionPrefix.For<T>()` in `DbConfig.Core` centralizes the rule.
  Multiple instantiations of the same open generic collide on one section —
  documented as a known limitation.
- **Whitespace tenant ids.** `ITenantResolver.Resolve()` returning
  `"   "` previously triggered a literal tenant lookup. The convenience
  overloads now treat null, empty, and whitespace identically and fall
  back to global. Explicit `GetForTenantAsync(tenantId, ...)` callers
  are unaffected — explicit caller intent is honored.
- **Silent defaults documented.** XML doc on `GetAsync<T>` and
  `GetForTenantAsync<T>` now calls out the silent-default-T behavior
  explicitly: bind returns a POCO with property defaults when zero
  section keys match (matches `IConfiguration.Bind()`).

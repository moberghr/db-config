# db-config — v0.10.1 Audit Log Page + UI Polish Spec

**Date:** 2026-05-19
**Status:** Shipped

## Goal

Add a global Audit Log page surfacing Insert / Update / Delete / Read events across all
scopes, including for keys whose entries no longer exist. Bundle several UI fixes
discovered during the v0.10.0 dogfood pass (dialog width capped at 290px, tree-view
checkbox misalignment, clickable-row affordance missing, enum serialized as integer).

Patch release — no breaking changes to the library surface.

## Scope Classification

- **Type:** moderate / additive feature + UI fixes
- **Implementation path:** subagent (audit page) + incremental fixes
- **Security impact:** low — audit data was already accessible via the per-key history
  endpoint; the flat `/audit` endpoint applies the same authorization model
- **Breaking-change risk:** none — public surface gains a method on `IConfigAuditStore`
  (default-implemented in the in-tree stores) and a new endpoint; existing endpoints
  unchanged

## Out of Scope (v0.10.1)

- Audit diff view on the global page (per-row dialog covers this; global page is
  list-only)
- Pagination beyond `?take=` cap of 1000 (cursor-based scrolling is a future ask)
- CSV export of audit results (could be a v0.11+ feature if requested)
- Custom Dialog `role="dialog"` (tracked from v0.7.0 review; standalone candidate)

## Public Contract Changes

### `IConfigAuditStore.QueryAsync` (new method)

```csharp
public interface IConfigAuditStore
{
    Task WriteAsync(ConfigAuditEntry entry, CancellationToken ct);
    Task<IReadOnlyList<ConfigAuditEntry>> GetHistoryAsync(
        string scope, string environment, string tenantId, string key,
        int take, CancellationToken ct);

    // NEW in v0.10.1
    Task<IReadOnlyList<ConfigAuditEntry>> QueryAsync(
        string? scope, string? environment, string? tenantId, string? keyPrefix,
        ConfigAuditAction? action, int take, CancellationToken ct);
}
```

`QueryAsync` is implemented in `InMemoryConfigAuditStore` (test helper) and
`EfCoreConfigAuditStore`. Custom store implementations must add the method.

### `GET /audit` flat audit endpoint (new)

```
GET {prefix}/audit?scope=&environment=&tenantId=&keyPrefix=&action=&take=
```

Returns `ConfigAuditEntry[]` ordered `ModifiedUtc DESC`. Default `take=200`, max `1000`.
Scope filter (`MapDbConfigHttp(scopeFilter: "X")`) enforced server-side — mismatched
`scope` returns 403; omitted `scope` is substituted with the filter.

### Enum serialization fix

`ConfigAuditAction` now serializes as its string name (`"Insert"`, `"Update"`,
`"Delete"`, `"Read"`) in HTTP responses. Previously serialized as the underlying integer.
This is technically observable but treated as a fix — clients deserialize fine via
`JsonStringEnumConverter` either way.

### Embedded asset serving

The `EmbeddedStaticFileMiddleware` is replaced with ASP.NET's `StaticFileMiddleware`
backed by an `EmbeddedFileProvider`. No public-surface change; just better cache headers,
range support, conditional GETs. Favicon (SVG) is now bundled by Vite and served like
any other asset.

## UI Changes

### Audit Log tab

- New top-of-page tab switcher: **Entries** / **Audit Log**
- `AuditLogPage.tsx` with table, filter toolbar (App / Env / Tenant / KeyPrefix /
  Action / Take), Refresh button
- Action chips color-coded: green Insert, blue Update, red Delete, grey Read
- Per-row eye toggle for secret old/new values (independent per row)
- Uses `queryAuditEntries({...})` client method (in `ui/src/api/audit.ts`)

### Dialog width fix

The custom Dialog primitive's inner wrapper was unsized; every modal capped at ~290px.
Fix: wrapper now `w-full`, so `max-w-6xl` / `max-w-4xl` / `xl` size props work as
intended. Edit + Create dialogs settled at `xl` (1152px) since their forms (Value
textarea, tenant input, scope dropdown) need horizontal room.

### Clickable rows

Pointer-events on row `<td>` cells (except the checkbox column, secret-reveal eye, and
action button column) now bubble up to a single row-level `onClick` that opens Edit.
Previously most cells silently swallowed the click. The eye and the per-row action
buttons keep their own `e.stopPropagation()`.

### Tree-view alignment

Leaf checkboxes and group chevrons now share the same X coordinate per depth. Group
rows render their content in a `colSpan` cell so the chevron lives in the same column
as a leaf's checkbox. Both indent via `paddingLeft = (depth + 1) * 28px` with subtle
vertical guide lines along the left edge.

### Softer dark mode

Background changes from pure black to off-black (`zinc-950` instead of `#000`). Row
hover contrast compressed slightly. Light mode is unchanged.

### Favicon

Vite emits a small SVG favicon; it's picked up by the embedded asset pipeline and
served at `{uiPrefix}/favicon.svg`.

## Sample (`samples/PaymentsApi`) Changes

- Seed now includes depth-0 secrets (`MasterEncryptionKey`), depth-1
  (`Stripe:WebhookSecret`), depth-2 (`Database:Primary:Password`), depth-3
  (`Notifications:Email:Smtp:Password`), depth-4 (`Features:Experiments:Checkout:V2:Enabled`)
- Varied audit history: `Stripe:DefaultCurrency` updated USD→EUR→GBP across three

  Delete event with no current entry
- Second `Notifications` app to exercise cross-Scope view in the flat endpoint

## Mechanism

`QueryAuditEndpoint.HandleAsync` validates filters, parses `action` against the
`ConfigAuditAction` enum (case-insensitive), and delegates to
`IConfigAuditStore.QueryAsync`. The EF store issues a single composite-index scan
ordered by `ModifiedUtc DESC` and applies filters via `IQueryable.Where` chains.

The UI's `AuditLogPage` calls `queryAuditEntries()` from `ui/src/api/audit.ts`; the
function shape mirrors the entries query (URLSearchParams, JSON response). Demo mode
adapter implements the query against the in-memory demo data set.

## Migration Impact

- **Consumers with custom `IConfigAuditStore`:** must implement the new `QueryAsync`
  method. Returning an empty list is acceptable if global audit isn't needed.
- **Consumers parsing audit JSON:** action is now a string (`"Insert"`) instead of an
  integer (`0`). `JsonStringEnumConverter` deserializes both shapes, but raw string
  comparisons against the integer form will break.
- **Consumers using v0.10.0 dialog sizing workarounds:** the size prop now works as
  intended; check that hand-rolled width overrides don't shrink the modal.

## Assumptions and Risks

| # | Item | Mitigation |
|---|---|---|
| A1 | Audit table grows unbounded; flat `/audit` can return up to 1000 rows × KB of value text | Default `take=200`; pagination is consumer concern; document retention SQL in `audit-retention.md` |
| A2 | Read audits (`AuditReads = true`) dominate row count, can make Audit Log page noisy | Action filter is in the toolbar; document the `Action != Read` filter as the common case |
| A3 | Dialog width fix could break consumer themes that depended on the narrow default | Acceptable — UI is part of the package, internal customization isn't a contract |
